CopernicusAI — an AI-powered engine for transforming literature, analysis and experimentation into scientific knowledge

📋 Summary

CopernicusAI is a working research prototype: scouts, embedding and a query interface run in production against three engines — GLMP (biology), ATAP (mathematics) and TDAP (topological data analysis, early stage). The architecture is domain-agnostic by design: what makes a field's engine is which literature its scouts watch and which flowcharts its researchers build, not a rewrite of the platform underneath. A new podcast briefing is generated only after at least three papers have been confirmed to exist in a registry (arXiv, PubMed or Crossref), and its reference list is built by code from those confirmed records. Quality scores and paradigm-shift notes are heuristic or model-generated, and are marked as such under Current Limitations.

The Research Tools Dashboard is a prototype web interface (first deployed December 2025) for exploring the knowledge graph, vector search, RAG question answering and content browsing. What is not yet verified or not yet built is listed plainly in the Current Limitations section.

🏗️ Knowledge Engine Architecture

CopernicusAI is organized in six tiers. A researcher works within a specific frontier — GLMP (biology), ATAP (mathematics) or TDAP (topological data analysis, early stage) — using the Knowledge Base UI as their instrument: the microscope they focus on that frontier, backed by Methods & Tools (the Programming Framework and its demonstration flowcharts). What they produce — podcasts, written papers — becomes new Resources, alongside metadata that Scouts bring in from the wider paper universe. A resource only becomes retrievable knowledge once it passes through Embedding, the gate between "exists in the collection" and "answerable by the Knowledge Base UI." That is the loop that makes this an engine rather than a pipeline: what a researcher produces today becomes what the next researcher finds tomorrow.

📥 Scouts & Ingestion

Scouts run twice daily against PubMed and bioRxiv/medRxiv. arXiv acquisition is currently failing because the arXiv API is rate-limiting requests (see Current Limitations). A NASA ADS harvester exists in the repository but has contributed no papers. Scouts add metadata to Resources alongside products (podcasts, papers, videos) from the researcher's own work.

⚙️ Embedding — the gate

A resource becomes retrievable knowledge only once it is vectorized into the shared corpus (Firestore + GCS) with an OpenAI embedding model. Not stored — findable. Embedded records: loading….

🎯 Mission & Methodology

Inspired by Nicolaus Copernicus's evidence-based challenge to accepted knowledge, CopernicusAI builds instruments for observing humanity's collective scientific knowledge — a growing index of research papers, regulatory and logical process flowcharts, and AI-generated podcast briefings in a single queryable knowledge graph. GLMP (biology) and ATAP (mathematics) are the two engines with process-chart databases; TDAP (topological data analysis) is a hosted engine at an early stage. A new briefing requires at least three papers confirmed to exist in a registry, and its references are built by code from those records; quality scores and paradigm-shift notes are heuristic or model-generated. The Copernican ethos applies to the platform itself: a marked limit is a finding, so limits are listed below.

🌟 Core Platform Capabilities

🎙️

AI-Powered Podcast Generation

Multi-voice AI podcasts of about 5–10 minutes that synthesize research papers. Generation is currently open to allowlisted subscribers only, each with a monthly quota. A subscriber can submit their episode to the public RSS feed; controls for private episode access are being rolled out in stages and are not yet complete.

What runs today:

  • ✓ Multi-speaker dialogue with ElevenLabs text-to-speech
  • ✓ AI-generated cover images (OpenAI gpt-image-1)
  • ✓ RSS feed distribution
  • ✓ Relevance gate: papers below an embedding-similarity threshold are dropped
  • ✓ Heuristic 0–10 research-quality score (not a validated measure)
  • ✓ Model-generated paradigm-shift notes (not independently validated)

Research integration:

  • ✓ At least three papers must be confirmed to exist in arXiv, PubMed or Crossref before generation proceeds (Zenodo records do not count toward the minimum)
  • ✓ Reference lists built by code from the confirmed records, not written by the model
  • ✓ Retrieval clients for PubMed, arXiv (with an OpenAlex fallback), Zenodo, bioRxiv, CORE, NASA ADS, news and YouTube; how reliably each one runs today is not measured here
  • ✓ Interdisciplinary connections: model-generated, not validated
  • ⏳ Source-verification metrics are being re-measured; no figure is claimed here until they are

🔍 Limitations & Future Directions

Current Limitations

  • • arXiv acquisition currently failing (the arXiv API is rate-limiting requests), so no new arXiv papers are arriving; a replacement via arXiv's OAI-PMH harvesting interface is planned. The arXiv records already in the corpus are not re-checked.
  • • Thin source coverage: the scouts that run are PubMed and bioRxiv/medRxiv. NASA ADS has contributed no papers. The corpus is therefore weighted toward biology.
  • • Verification metrics are being re-measured: how often a cited source is confirmed and relevant has no published figure here until the re-measurement finishes.
  • • Generation is not open: only allowlisted subscribers can generate podcasts, within a monthly quota. Private episode access is pending.
  • • Heuristic and model-generated scores: the research-quality score is a heuristic; paradigm-shift notes and interdisciplinary connections are written by a model and are not independently validated.
  • • LLM accuracy: generated content relies on LLM accuracy; requiring three confirmed sources and a relevance gate reduces but does not eliminate errors.
  • • Update cycle: the corpus updates on scheduled scout and ingest cycles (twice daily), not in real time; counts above are as of the date shown.
  • • Engine maturity: TDAP is at an early stage; engine-specific scouts are in development.
  • • Language: the corpus is English-language research papers.

Planned (not built)

  • • arXiv through OAI-PMH: a replacement harvesting route via arXiv's OAI-PMH interface
  • • Engine-tuned scouts: scouts aimed at each engine's research frontier
  • • Private episode access for subscribers
  • • Per-paper entity extraction, citation networks and stored quality scores
  • • Advanced video features: dynamic visualizations, animations and multi-layer composition
  • • Multi-language support: non-English research papers
  • • Enhanced validation: peer review mechanisms and user feedback integration
